# Explicar um projeto

A explicação deve ajudar uma decisão do usuário, como assumir a manutenção, pedir uma mudança ou avaliar uma entrega. Identifique essa decisão no pedido; pergunte apenas se sua ausência impedir uma explicação útil.

Leia o material autorizado sem executar o projeto ou alterar arquivos. Use os nomes e exemplos reais do material, omitindo segredos e dados pessoais desnecessários. Se receber apenas uma descrição, limite as conclusões a ela.

Conecte cada parte técnica ao efeito para quem usa o produto. Por exemplo, explique que uma fila distribui tarefas para processamento posterior antes de apresentar o nome da tecnologia. Não invente analogias que mudem o comportamento descrito.

Diferencie o que o código permite fazer, o que a configuração declara e o que foi observado em execução. Um arquivo de implantação não comprova a versão no ar. Cite caminhos ou documentos nas conclusões relevantes.

Entregue uma explicação proporcional ao pedido, com propósito, partes principais, lacunas e próximo passo. Não transforme desconhecidos em defeitos nem uma explicação em autorização para corrigir o projeto.
